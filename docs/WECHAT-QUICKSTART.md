# 微信识别：手机上这样试

当前使用 0.4 测试包，应用名称「记一笔 · 付款识别」。APK 已单独交付，不放入源码仓库；自行生成请看[构建说明](../README.md#从源码构建)。同签名测试包可直接覆盖原测试版，不必卸载；卸载会删除本机账本。换电脑构建的调试签名可能不同，不能直接覆盖。包名保持不变，原有来源设置保留，微信需要单独选择。0.4 的支付宝三类页面变化见 [支付宝实图自测](ALIPAY-REAL-SAMPLES.md)，本页微信步骤保持不变。

## 第一次打开

首次显示四步图文指南：选择并授权 → 付款后自动检查 → 手动触发 → 核对结果。可以点「稍后设置」或关闭；以后在 **自动 → 使用指南** 或 **设置 → 使用指南** 随时重看。

引导里的手势是 Android 的最近任务切换方式，不是摇一摇或双击背部的识别快捷键。读指南不会开启采集。

## 先试自动识别

1. 底部点 **自动 → 微信 → 同意并选择微信**。
2. 打开 **付款页面读取 → 同意并开启页面读取**，按系统提示开启「记一笔」的支付页面读取服务。
3. 回到应用，确认付款页面读取显示 **已连接**。只有“已授权”但未连接时还不能读取。
4. 正常完成一笔微信消费付款，在付款成功页停留片刻；也可以打开这笔付款的账单详情。不要为了测试额外付款，正常消费时试即可。
5. 回到 **明细**，核对商户、金额、渠道和笔数；如显示“需要核对”，检查后再点 **确认并入账**。

付款凭证需要明确的成功状态与人民币金额。页面缺交易时间、缺商户、存在多个金额或疑似重复时，不直接计入统计；缺有效金额不会创建零元记录。旧账单可能进入待核对，请勿误当新消费重复确认。

通知读取是可选补充：在 **自动 → 通知读取** 授权。微信没有发送系统付款通知时，这条路径不会触发。聊天类通知会过滤，其他微信通知解析出的付款候选也需核对。

## 没记录时，手动识别一次

需要 **Android 14 或以上**、页面读取已连接，并在 **自动 → 截图 OCR** 单独同意开启。

1. 先停留在微信的付款成功页或单笔付款详情，再切回记一笔。
2. 点 **自动 → 识别当前付款页**，选择 **微信**。
3. 点 **开始 8 秒倒计时**。
4. 从底部上滑并停住，进入最近任务，再点回微信付款页；三键导航直接点最近任务键。
5. 等待一次识别，再回到明细核对。所有 OCR 结果都先进入待核对，确认前不计入统计。

倒计时期间回到“自动”可点取消。锁屏、切错应用、权限关闭、服务断开或页面禁止截图时会停止。不要在聊天、密码、银行卡等敏感页面发起识别。

## 检查这些结果

- 微信记录的渠道显示“微信”，支付宝功能仍可使用。
- 同一凭据再次处理不应重复累计；相近且无法证明相同的多份凭据会待核对，不按“同金额”擅自合并。
- 微信通知和 OCR 记录未确认前不进入收支统计。
- 关闭微信选择后，不再采集微信；停止全部采集后，原账目仍保留。
- 首次指南关闭后不反复打扰；两个回看入口都可以打开相同的图文步骤。
- 深色模式、系统大字号和横屏下，步骤及按钮能完整滚动查看；减少动态时不依赖手势动画也能读懂。

红包、转账、收款、退款暂不自动记为消费。无文字页面只有主动单次 OCR；自动 OCR 仍需先读到付款凭证及成功线索。

## 排查与反馈

无记录时先看 **自动 → 查看诊断记录**。可用 **导出诊断文件** 保存本地 JSON 后再决定是否分享；文件不含完整通知/页面文字、商户、金额、交易号或截图。

如反馈问题，请提供：微信版本、手机/系统版本、触发方式（自动页面 / 通知 / 手动 OCR）、操作时间、结果（无记录 / 待核对 / 重复 / 错金额）及诊断代码。不要提供支付密码、验证码或完整交易号。荣耀后台设置提示可在 **自动 → 荣耀手机权限与后台设置** 重看。

本轮未运行安卓模拟器或真机测试。当前构建和本地规则测试结果见 [0.4 核验记录](../artifacts/ALIPAY-SAMPLES-VERIFICATION.md)；真实模板覆盖与实际显示效果由上述手机操作确认。
