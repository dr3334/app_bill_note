# 墨色清单交互与动效审核

日期：2026-10-17。目标设备：荣耀 100 Pro / MagicOS 10。固定方向：墨色清单，底部四项 **明细 / 统计 / 自动 / 设置**。

本次只读旧原型和现有研究，提出设计与验收要求；没有启动浏览器、运行原型、安装 APK 或做支付实测。下列时长是建议的设计参数，不是荣耀官方规范，也不代表目标手机已验证。新原型的成功、待确认、重复、失败、权限失效场景必须明确标为模拟。

## 1. 先修正的交互问题

旧原型的墨色、清晰金额和四项导航值得保留，下一版优先修正这些问题：

1. **开启偏好不能代表采集正常。** `active` 同时把微信与支付宝显示为“已开启”，初始值还默认为真。应分别呈现“用户愿意开启”“必要授权是否具备”“服务当前是否连接”；没有新记录不能推断采集失败，也不能据此声称没有漏账。
2. **自动成功必须直接入账。** 现有示例每笔都先确认商家与分类，无法证明零操作目标。支付事实充分且去重检查通过时直接入账；只是分类不确定，可先放“未分类”，之后修改。金额、币种、收支方向或付款成功状态存疑，才要求核对。
3. **记录级状态取代一个全局 `confirmed`。** 当前一次确认同时控制条目、总额、去重和待确认提示，只能表现一张样例。下一版至少用不同记录标识演示两笔独立交易、重复凭据及重试，不能把“已确认过”当成“重复”。
4. **补齐导航与编辑上下文。** 明细行应可进入详情；从“自动”进入核对后返回“自动”，保留筛选、滚动位置和未提交字段。当前 `innerHTML` 整体替换、返回固定明细，容易丢焦点与上下文。今日明细还需按时间统一排序，不能混排 09:42、12:16、08:31。
5. **统计需要可操作的证据。** 只有“退款冲减消费”的说明不足以验收；须有退款、转账、跨月退款的样例和可回溯明细。保存成功后，列表、预算、分类统计从同一笔已提交记录更新。

## 2. 精简页面清单

四个根页面保持稳定，异常使用同一详情页的状态变体，避免为每个结果新建导航层级。

| 页面 | 首屏任务 | 必须可操作的内容 |
| --- | --- | --- |
| 明细 | 看清近期收支与待处理事项 | 月份切换、搜索/筛选、记录详情；待核对入口；新增入口 |
| 统计 | 理解选定期间的钱花在哪里 | 期间选择、消费/退款/净支出口径、分类下钻到同一批明细；空数据态 |
| 自动 | 了解自动能力是否可用、处理异常 | 微信/支付宝各自状态，最近一次收到信息的时间与来源，待核对/失败队列，来源设置入口 |
| 设置 | 管理账本与隐私 | 账户、分类、预算、备份导出、权限与原始凭据保留策略；未实现入口明确“演示” |
| 账目详情／核对页 | 看证据、修正这一笔 | 金额、方向、商家、时间、分类、支付渠道与扣款账户、来源；仅突出存疑字段；退款关联、排除/恢复 |
| 来源设置页 | 授权、暂停与恢复一个来源 | 用途解释、当前系统状态、去系统设置、返回后重新检测、已验证支持范围与限制 |
| 补记面板／导入结果页 | 在自动覆盖不到时补全 | 截图、账单文件、手记入口；真实选中数量；新增/重复/待核对/失败结果；批次撤销 |

首页 `+` 建议打开“记一笔”面板；若只提供截图，则使用扫描图标与“截图补记”标签，避免按钮图义与结果不一致。二级页隐藏 Dock，使用明确返回；四个根页面各自保留滚动位置。详情可编辑，不能只有一张不可操作的收据。

金额层级保持清楚，状态与元数据适度退后；不要让每行重复出现两次相同时间。默认不通过数字滚动动画展示余额变化。

## 3. 两套独立状态，分别回答两个问题

### 来源状态：现在能否接收信息？

| 状态 | 展示与动作 |
| --- | --- |
| 未开启 | “自动采集未开启”；说明用途，再由用户启动授权流程 |
| 需要授权 | “需要通知访问权限”等准确原因；去系统设置；取消后保持未开启 |
| 可用 | “通知采集可用”等已检测到的具体能力；注明最近接收时间，不写“所有付款已同步” |
| 部分可用 | 例如通知可用、页面识别不可用；逐项说明，保留仍可工作的通道 |
| 暂时中断 | “连接已中断”；给重新检测/恢复操作，展示中断期间可能未收到信息的事实 |
| 当前不支持 | 指明该能力在当前版本或发布渠道不可用，提供补记入口，不能反复催用户授权 |
| 用户已暂停 | 与权限失效区分；显示“已暂停”，由用户恢复 |

权限开关表达用户偏好，状态检测表达系统事实，两者不能合并。支付应用更新或长时间没有事件，不应自动宣告“权限失效”。重新连接成功只代表现在恢复，不能宣告中断期间的记录已自动补齐。

### 单笔处理：这条信息是否已成为账目？

**收到信息 → 识别与校验 → 去重判断 → 已入账 / 待核对 / 已关联重复凭据 / 处理失败 / 不属于交易。**

- **已入账：** 必要交易事实可靠，直接保存。商家或分类缺失可用“未知商家 / 未分类”；不能为凑齐美观字段阻塞自动入账。必要时间信息不足时明确其来源，例如“接收时间”，不得伪造支付时间。
- **待核对：** 不进入正式支出、预算和分类统计；卡片显示原因，例如“金额有两种识别结果”。编辑后校验并一次提交；可暂存、忽略。不要把失败或重复混进“待核对”总数。
- **重复：** 确定为同一交易时只关联新凭据，不增加金额；可查看既有记录。仅金额、商家、短时间接近属于“可能重复”，展示两笔差异，允许“保留两笔”；不得自动吞掉第二笔合法消费。
- **失败：** 没有生成新账目，提供可执行的下一步。图片模糊提示重新选图；暂时处理错误提供重试；受保护页面无法读取时明确当前方式不可用。保留用户已填字段，重试仍用同一任务标识，避免多记。
- **不属于交易：** 不计账，默认安静处理；导入批次中可显示“未发现付款记录”，允许查看原因。

原型“模拟付款”按钮只是测试触发器，应放在明确的“演示控制”区。正常产品不能要求用户每次按一次才能称为自动。真实来源没有收到事件时，不应播放假的“正在识别”或成功动画。

## 4. 反馈、异常与统计口径

**App 内状态胶囊**只在真实处理时显示进度，完成后短暂显示“已记入 ¥32.80 · 未分类”，点击进入详情；待核对与失败同时保留在处理队列中。胶囊不遮挡金额、输入框或 Dock，不抢焦点。它不等于荣耀官方实况窗、系统胶囊或 YOYO 系统入口，原型也不应暗示已取得这些集成。App 外反馈另行依赖经授权且实际可用的系统通知，不自动弹出跨应用浮层。

| 情况 | 反馈与恢复要求 |
| --- | --- |
| 权限失效 | 自动页持续提示具体失效能力；首页一条轻提示；返回系统设置后重新检查。取消授权不循环弹窗 |
| 重复导入 | “已在账本中，未重复记入”；可查看原记录。部分重复批次显示各状态数量 |
| 提交处理中 | 主按钮显示处理中并防重复提交；仍允许合理返回；完成结果可在原队列找到 |
| 批量导入 | 已完成数量以实际结果计数，不做假百分比；显示新增/重复/待核对/失败，各项能下钻 |
| 撤销 | 撤销本次新增或用户变更，不能删除其他来源已有的同一交易；记录详情保留恢复入口，不能只依赖几秒提示条 |
| 空白账本 | 简短解释自动记录条件，提供开启和补记入口；样例数据不得混进真实统计 |
| 离线 | 本地能力可用则继续；依赖网络的步骤准确提示，不能把整个 App 一概标为不可用 |

首版统计建议明确：**本月净支出＝本月消费－本月到账退款**。消费、退款分别可查看；跨月退款计入到账月，并可追溯原消费，历史月不静默改写。转账与信用卡还款保留流动记录，不再重复计算消费。只确认发生了退款但不能对应原消费时，作为待关联退款保留，不能默默分配到一个消费分类。若某分类退款大于消费，应能显示负净额，不能绘制误导的饼图占比。具体口径需与账务实现统一。

## 5. 动效参数建议

以下是起始参数，后续按真机调校。一次状态变化最多突出一至两个元素；入账、返回、保存不依赖动画播放完成。快速连点或切页必须取消旧动画并落到正确最终状态。

| 场景 | 建议时长 | 目的与限制 |
| --- | --- | --- |
| 按压反馈 | 80–120 ms | 点击后尽快出现状态层；松开恢复 120–160 ms；避免整张大卡明显缩放 |
| Dock 切换 | 140–200 ms | 选中态与内容轻淡入；无四页横向长滑动；保留各页位置 |
| 进入详情／底部面板 | 240–300 ms | 轻位移与淡入，退出 180–220 ms；原生返回手势优先跟手 |
| 入账胶囊状态变化 | 160–220 ms | 进度变成功/待核对，文字不跳动；成功反馈约 3–4 秒后收起 |
| 新记录出现 | 160–220 ms | 淡入加不超过 8 dp 的轻位移；用户正在翻旧账时不强制滚回顶部 |
| 分类图初次出现 | 240–360 ms | 只做一次低幅度展开；金额立即显示正确值，不做逐位计数 |
| 含撤销的提示条 | 建议至少 6–8 秒 | 按无障碍设置延长；详情另有可持续找到的撤销/恢复操作 |
| 减少动态效果 | 关闭位移、缩放、图表展开 | 瞬时更新或短淡入；保留文本状态与按钮反馈，不用动画传递唯一信息 |

OCR、图片解码和统计重算不占用 UI 主线程。动效实现优先使用已有 Android 导航、列表、状态层和系统动效设置；不为了动效重写现有 UI 框架。HTML 原型用 `prefers-reduced-motion` 表达减少动态效果，不能据此宣称原生 Android 已适配。

## 6. 原型与后续原生验收

### 可互动原型必须覆盖

| 测试场景 | 合格条件 |
| --- | --- |
| 可靠支付信息、分类未知 | 无逐笔确认直接新增；标未分类；明细、当日、月净支出与预算一致 |
| 金额不确定 | 进入待核对；正式统计不变；可修改金额，不只商家/分类 |
| 同一凭据重复输入 | 正式账目只一笔；总额不变；可打开已有记录 |
| 同商家同金额的两笔合法交易 | 有不同交易标识或明确证据时保留两笔；不能按文本近似静默丢弃 |
| 识别失败后重试 | 有具体原因与下一步；重试不会产生两笔；已有输入保留 |
| 权限撤回、恢复或取消恢复 | 微信与支付宝/各采集能力各自显示真实状态；恢复不宣称历史漏账已补齐 |
| 连点保存、切页再返回 | 一次提交；没有重复扣预算；返回到原入口且字段/滚动上下文合理保留 |
| 退款与转账 | 消费、退款、净支出可追溯；跨月退款按明确口径；转账不重复算消费 |
| 批次部分成功与撤销 | 数量合计正确；可逐项处理；撤销不误删之前已有记录 |
| 正常/大字体、键盘、减少动态效果 | 主操作可见、可点击、可取消；无内容被 Dock 或键盘遮挡；关闭动效不影响结果 |

### 荣耀原生阶段另行验收

- 真机上按 **48 dp** 最小触控范围检查，不能把原型 48 CSS px 直接当成已通过设备验收；大字体不截断金额、错误原因和关键操作。
- 校验顶部与手势导航安全区域，底部 Dock 与最后一条明细留足空间；系统返回、输入法返回与详情返回顺序正确。
- TalkBack 可读出金额、收支方向、来源、状态与操作名称；图表有等价文字；状态更新不抢焦点、不重复播报。
- 正文对比度目标至少 4.5:1，重要图标与控件边界至少 3:1；深浅主题分别测量；不能用低饱和灰和颜色差异替代状态文字。
- 在荣耀 100 Pro / MagicOS 10 实际记录帧耗时、输入响应与后台恢复结果；在当前支持的支付版本逐场景测零操作覆盖率。HTML 演示、其他品牌手机结果和手动打开详情触发，均不能代替该项证明。
