# 「记一笔」界面与动效设计提示词

2026-10-17。已确认方向：**墨色清单＋底部 Dock**；四项固定为 **明细 / 统计 / 自动 / 设置**。首要设备为荣耀 100 Pro / MagicOS 10。以下四段可直接复制使用；先贴总提示词，再追加当前页面或动效任务。页面稿、可交互原型、安卓真机实现应分别标注完成程度。

## 1. 总提示词

```text
你是资深安卓产品设计师。为中文自动记账 App「记一笔」设计可实际使用的界面，沿用已经选定的“墨色清单＋底部 Dock”，完成这一方向，不再提出风格投票。

产品核心：把微信、支付宝支付后的可用信息变成准确账单；用户主要浏览明细、处理少量待确认项、查看统计和检查自动记账状态。它应像一本克制、清晰的个人账册。不要做营销首页、功能宣传卡片墙、科技仪表盘或玻璃风概念图。

视觉语言：暖白或浅纸灰底、墨黑主文字、清楚的细分隔线、充分但不空洞的留白。优先通过字号、字重、对齐和间距建立层级。主要内容以清单为骨架，卡片只用于确有分组意义的区域；不把每条账单套入大圆角卡片。Dock 使用不透明面板和墨色选中块、四项图标加中文文字，深色主题采用对应反色，独立于系统导航区域；不要依靠大面积模糊与发光制造质感。设置少量有功能含义的强调色；待确认、错误、已完成要同时有文字或图标，不能只靠颜色。

文字与数字：使用适配中文的系统字体，不强加拉丁手写字体或不明许可字体。金额使用等宽数字特性、清晰币种与正负号，金额列右对齐；商户名左对齐。正文以 16sp 为起点，辅助文字通常 13–14sp；数字和标题按层级放大。这些是初始设计值，必须支持系统字体放大。长中文、超大金额和负数不能挤坏布局。

结构：底部 Dock 固定四项“明细 / 统计 / 自动 / 设置”，图标家族、尺寸和描边统一，选中态同时用形状/字重/语义表示。待确认数量是未完成工作数量，不能因打开页面就清零。四个目的地保持各自筛选、滚动和输入状态；返回遵循安卓平台习惯。底部安全区、键盘及曲面屏边缘均留足可用空间，滚动末项不能被 Dock 遮住。触控目标至少 48dp，相邻重要动作留出间隔。

账务语义：识别到信息≠已记录；低把握≠支付失败；疑似重复≠确认重复。待确认不计入正式统计；已确认重复不新增支出。只有实际保存完成后才能展示“已记一笔”。真实支付失败、识别失败、保存失败分别表达。示例数据必须标注为演示，不用假精度或假进度冒充能力。

荣耀胶囊：优先设计适合系统胶囊表达的短状态，但其开放接口、准入、机型支持、允许的场景、交互和显示期限仍待官方核实与真机验证。将“系统胶囊候选体验”和“App 内顶部状态条”作为两种独立载体。未经核实不得声称后台任意展示、跨应用自由悬浮、精确控制系统尺寸/动效，或把 App 内组件画成已经接入系统的证据。系统不可用时，产品流程仍能完整完成。

先交付真实页面和完整状态，再打磨动效。输出应包含：页面层级、关键组件尺寸与语义 token、真实中文文案、状态转换、可交互路径与尚未验证的系统依赖。遵循现有工程技术栈，复用现有账单/分类/编辑能力，不为了视觉改版重写一套框架。
```

## 2. 页面提示词

```text
沿用「记一笔」总提示词，完成同一套可点击页面。每页给出首屏、滚动后、空状态和必要异常状态，保持同一份演示账本数据。页面以用户当前任务排序，主操作只保留一个视觉重心。

明细：顶部为月份切换与搜索/筛选；简洁展示本月已确认支出、收入，不让概览挤掉账单。待确认存在时显示明确入口“3 笔待确认”，不弹出阻断式警告。按日期组织清单：分类图标、商户/用途、时间与来源、右侧金额。点击账单进入详情，保留返回位置；必要的手动添加入口可见但不争夺自动记账主线。空状态说“还没有账单”，给“导入一张截图”和适用的开启自动记账入口。不要显示虚构交易填满空页面。

账单详情与编辑：金额、收支、分类、商户、时间、账户为清楚的字段；识别来源和原始证据通过展开查看，默认避免把完整隐私截图铺满页面。金额不确定时直接标在金额字段旁，解释“未识别出金额，请补充”，不要只显示置信百分比。主操作“确认入账”；次操作“暂存”或“忽略”。键盘弹出后主操作仍可到达；返回保留草稿或明确处理未保存更改。成功后回到原清单位置并提示结果，允许撤销误操作，不强迫看完庆祝动画。

统计：月份选择、收支摘要、支出类别横向条形图、趋势和对应明细入口。直接标出类别、金额及比例，不要求只凭色块判断；提供可读文本/列表替代。正式统计明确排除待确认项，展示其数量作为独立提示。退款口径清楚，异常或缺失数据不画成零值。空数据、加载失败、跨月切换分别设计。图表进入时数值即可读，不逐个滚动金额。

自动：首屏回答“现在能否自动记账、最近处理了什么、需要我做什么”。用有依据的状态文案，如“通知读取已开启；最近收到一条通知”，不要仅凭一个权限开启就承诺全程正常。微信、支付宝分别展示已配置的采集方式、最近一次实际接收/识别时间及需要处理的问题；没有实际事件时写“尚未收到可识别信息”。提供导入截图测试入口。权限说明按使用时机展开，不把首次进入做成一页必须全开的开关墙。

设置：数据与隐私、导入导出/备份、显示与动效、自动记账权限诊断、关于。备份/云端识别如果尚未实现，要明确标注或不作为可操作功能展示。金额隐藏、系统深色模式、减弱动态和触感反馈有清楚状态。关闭功能、清空数据等动作与普通设置保持视觉距离。

补齐以下处理状态，确保任何状态都能继续完成任务：
- 待确认：“有一笔需要确认”，显示原因及缺失字段；“查看并确认”，暂时不计入统计。
- 疑似重复：“可能与 14:32 的一笔重复”，并列金额、时间、商户、来源；提供“是同一笔”和“是两笔”。不要让系统未经充分证据就用勾号宣布合并成功。
- 确认重复：“这笔已记录”，链接原账单；保留来源信息，允许纠正误判；不新增金额、不再播放一次入账成功动画。
- 识别失败：“没识别出金额，截图已保留”，给“补充金额 / 重新识别 / 删除截图”；若截图实际未保留则改用真实文案。不要把失败记录生成 ¥0.00 账单。
- 保存失败：“暂未保存成功”，保留已填写内容和可恢复的草稿，给重试；不得显示已记账。
- 权限失效：“自动采集已暂停”，说明具体失效项、受影响范围，提供打开对应设置/查看步骤和导入截图的备用路径；从设置返回后重新检查，不直接假定恢复。

为荣耀系统胶囊候选提供一组短文案：“正在识别 / 有一笔待确认 / 已记一笔 / 自动采集已暂停”。默认隐藏商户和金额，隐私显示由用户选择且遵循系统限制。只有系统能力确认后才设计其可用点击/展开动作；候选图必须标注“系统接入待验证”。App 内顶部状态条使用自己的安全区，不覆盖摄像头、状态栏或其他 App，不申请悬浮窗来伪装系统胶囊。通知或状态入口的深链接要回到对应账单或问题，不统一扔回首页。
```

## 3. 动效提示词

```text
为已确定的「记一笔」界面补充克制、可中断的动效。每段动效必须说明：触发事件、起止状态、用户获益、动画载体、节奏、可取消行为与减弱动态替代。不要仅给一段形容“丝滑”的视频。

优先采用适合工具类界面的标准、低回弹弹簧反馈；目标改变时衔接当前值与速度，不从旧起点重播。现有 Android View/XML 工程可复用平台生态的 SpringAnimation，不强制迁移 Compose，也不把网页 GSAP 预演代码当成安卓实现。

先建立设计用的初始节奏目标：按压反馈约 90–120ms，小范围状态替换约 160–200ms，详情/底部面板进入约 240–300ms；退出可比进入短。这些毫秒仅为本项目感知目标与网页预演近似，不是荣耀或 Material 的官方规定，也不替代原生弹簧的阻尼/刚度参数。按距离、复杂度和真机效果调整，不能当作所有组件的统一定律。信息立即可用，动画不得拖延可操作性。使用少量透明度、颜色状态层或短位移；避免大幅缩放、持续呼吸、粒子、数字翻滚及满屏交错入场。

1. Dock：按下立即反馈，选中指示保持连续；文字和图标基线稳定。切换保留页面滚动位置，不让整页从屏幕外飞入。快速连点时取消旧动效并直达最新语义状态，不排队播放。
2. 明细到详情：让用户认得同一笔金额和商户，使用轻量淡入或有依据的连续过渡；返回恢复原位置。遵循实际安卓返回机制，不能画出工程无法实现的系统交互。长列表滚动不反复做逐行入场动画。
3. 自动处理：接收→识别中→已保存/待确认/失败为不同业务状态。近乎瞬时的成功不闪一下加载；确需等待时展示真实状态，不造百分比；超时提供恢复操作。当前不在相关页面时，不强行打断用户。
4. 入账反馈：收到持久化成功结果后，状态条短暂显示“已记一笔”，相应新行做一次低强度强调。若用户正在查看历史账单，保留视口，显示“有 1 笔新记录”，点击后再定位。动画完成事件不能承担保存、修改统计或清零待确认的职责。
5. 待确认与重复：通过文字与局部强调解释下一步，不使用错误抖动责备用户。疑似重复选择完成后显示实际结果；误判可恢复。屏幕阅读器读完整短句，如“还有 2 笔待确认”，不只读数字，不抢焦点，不让多个组件重复播报。
6. 面板：跟随触发位置或使用平台底部面板过渡，明确关闭/返回入口。拖拽有按钮替代，输入未保存时保留草稿。减弱动态开启时直接出现最终位置或用极短淡入。
7. 图表：不为了动效改变真实比例、金额和坐标；月度切换可在固定容器内短交叉淡入，数字立即可读。默认没有循环动画。
8. 触感：只在用户明确操作的关键确认等少量位置考虑轻触感，并可关闭；不要每条后台采集都振动。系统胶囊的动效由系统能力约束，App 不承诺控制其物理形态、弹性或停留时间。

减弱动态是完整模式：关闭位移、缩放、共享元素飞行、数字滚动与装饰循环；保留静态进度文字、状态变化和清楚焦点。响应平台动画偏好，并提供 App 内减弱动态选项；平台取值尚未接入时要明确说明。无动画也必须可完成全部任务，不能以动画结束回调推进业务。

交付常规与减弱动态两个版本的可交互演示，并能演示连续点击、处理过程中返回、切入后台再返回及失败重试。标注哪些只是原型模拟，哪些已通过荣耀真机验证。
```

## 4. 验收提示词

```text
以中文个人记账 App 的实际使用者和安卓无障碍审查者身份，验收「记一笔」界面及动效。逐项给出“通过 / 不通过 / 未验证”，提供页面、复现步骤和观察到的证据。静态稿不能证明真实保存、系统权限、性能或荣耀胶囊接入。

A. 视觉：是否保持墨色清单、四项 Dock“明细 / 统计 / 自动 / 设置”？是否有营销组件、过量卡片、玻璃模糊或无意义装饰抢走账单？金额对齐、中文字体、图标描边、主题 token 是否一致？普通文字含辅助文字对比至少 4.5:1，必要图标/边界至少 3:1，浅深色主题分别测量。
B. 页面与安全区：在小屏、荣耀目标设备、横屏和大字体下检查。至少覆盖 200% 字体、长中文商户、-¥123,456,789.90、空/一条/大量账单、键盘打开。48dp 触区、系统手势区、屏幕顶部开孔和 Dock 底部留白是否正确？最后一条账单和表单错误能否滚动到且完整操作？布局用可用 dp 和系统 Insets，不能按截图物理像素硬编码。
C. 导航：切换四项后再回来，筛选和滚动是否保留？详情返回、编辑返回、系统设置返回是否可预测？重要操作有没有只靠滑动或长按的隐藏路径？Dock 标签和选中态能否被屏幕阅读器正确理解？
D. 状态：依次演示正常保存、金额缺失、疑似重复、确认重复、识别失败、保存失败、权限失效、权限重新开启。失败后输入不丢；没有生成 0 元假账单；重复不累计；待确认不计入统计且数量只随实际处理减少；不把支付失败和识别失败混写。撤销误操作后数据与界面一致。
E. 动效：快速连续点击 Dock、连续出现两笔账单、处理未结束就返回、滚动历史时有新记录，是否出现错位、跳顶、旧状态覆盖新状态或误重复？动画期间仍能操作；动画关闭时语义和数据都正确。最多突出少量关键元素，不靠动画掩盖加载或主线程卡顿。性能在实际刷新率下测量；没有真机帧耗时数据就标未验证。
F. 无障碍：减弱动态能走通所有路径；字体放大不遮操作；状态/错误有文字与读屏反馈；焦点顺序合理、不被状态条或键盘挡住；图表有文字/列表替代；触感、颜色、手势都不是唯一信息渠道。
G. 荣耀胶囊：单独列出“设计候选 / 官方能力已证实 / 真机已验证”。未验证系统准入、后台展示和交互时不得写已支持。关闭胶囊、拒绝通知或权限失效时，App 内流程是否仍完整？锁屏与跨应用状态是否默认保护金额和商户？只画出胶囊外形不算接入通过。

只列真实发现，按影响排序给出小范围修改建议；不要重新推翻已确认风格。验收结束说明仍未验证的系统能力和运行条件，不把视觉通过等同于可以上架。
```
