# 记一笔界面与动效基线

版本：2026-10-17。用户已确认 **墨色清单＋底部 Dock**，先完成设计，再进入荣耀 100 Pro / MagicOS 10 的原生适配。产品名称暂用“记一笔”。

## 已确定的界面方向

暖白背景、墨色文字、细分隔清单；层级依靠金额、字号、留白和对齐。四项 Dock 固定为 **明细 / 统计 / 自动 / 设置**，采用不透明面板与墨色选中块，深色模式对应换色。账目不逐条套大卡片；不用玻璃模糊、霓虹、粒子和持续呼吸作为装饰。

金额右对齐并使用等宽数字特性；支付渠道与扣款账户分开，未取得的账户写“未获取”。可靠支付信息可以直接入账，缺分类可暂记“其他”，不让普通交易逐笔确认。只有金额、状态或交易身份不确定时进入待核对。

## 页面范围

| 页面 | 当前交互预演 | 原生开发前须补齐 |
| --- | --- | --- |
| 明细 | 月支出、收入、预算剩余、日期分组、待核对入口、自动新增记录 | 月份选择、搜索筛选、空账本、长列表滚动位置保持、手动新增与撤销 |
| 详情与编辑 | 查看、修改商家/金额/分类、金额校验、待核对确认、重复不增加金额 | 原始凭据、收入/转账/退款编辑、保存失败、退出草稿恢复、系统返回 |
| 统计 | 同一份演示账本汇总、类别条形图、预算调整、隐私模式 | 月/年切换、趋势与下钻、跨月退款、空数据与查询失败 |
| 自动 | 微信与支付宝分别显示来源状态、恢复指引、截图补记、批量导入 | 真实权限探测、来源方式、最近事件、诊断与导入取消/失败项 |
| 设置 | 浅深色/跟随系统、隐藏金额、减少动态、预算、通知隐私 | 系统字体、触感开关、导出备份、删除联动与应用锁 |

“当前交互预演”仅指浏览器中的本地模拟。支付采集、相册/系统设置、数据库落盘、系统胶囊及原生触感均未接通。原生开发前须补齐项是后续页面设计范围，不因当前预演可点击就标为已完成。

## 状态与文案

自动来源状态与单笔账目状态独立维护。权限开启不等于每次付款可取得数据；某笔识别失败也不等于支付失败。

| 单笔状态 | 反馈 | 账务变化 |
| --- | --- | --- |
| 接收、解析中 | “正在识别付款信息” | 无 |
| 持久化完成 | “已记一笔”，可查看 | 新增一次正式账目，并更新同一份统计 |
| 金额等信息不确定 | “金额需要核对，已保存草稿” | 待核对数量增加；不计入支出 |
| 已证实重复 | “这笔已经记过，没有重复添加” | 关联原记录，不再次增加金额 |
| 疑似重复 | 对照两笔信息，允许保留两笔 | 未判定前不得擅自合并 |
| 识别失败 | “图片不清晰，未生成账目” | 不生成零元账目；可重选/补充 |
| 保存失败 | “暂未保存成功”并保留内容 | 不播放成功反馈，允许重试 |
| 来源失效 | 指明微信或支付宝及受影响范围 | 已有账目可用，恢复后查漏 |

不同凭据即使同金额同商户也不能仅凭外观当成一笔。相同凭据重新识别、重复确认和通知重发必须保持幂等。

## 动效语言

采用工具类界面的标准低回弹运动；用户操作立即响应，转场可中断。原生 View 工程优先复用 [Android SpringAnimation](https://developer.android.com/develop/ui/views/animations/spring-animation)，不因改版强制迁移 Compose。运动语言参考 [Material Motion](https://m3.material.io/styles/motion/overview/how-it-works)；以下时长为本项目网页预演的起点，不是荣耀官方参数。

| 场景 | 预演节奏 | 原生实现要求 |
| --- | --- | --- |
| 按压 | 100 ms 的明暗/透明度反馈 | 命中区域不移动，48dp 触区 |
| Dock 切换 | 指示块 220 ms；内容 200 ms、8px 以内位移 | 快速切换接续当前值，保留各页位置，不排队 |
| 详情面板 | 进入 300 ms / 退出 180 ms | 原生底部面板；返回可中断，关闭后焦点合理恢复 |
| App 内状态替换 | 260 ms、小范围淡入和位移 | 读屏播报完整短句，避免抢焦点和重复播报 |
| 新账目入列 | 220 ms、10px 以内一次强调 | 只在保存完成后展示；查看历史时保留视口 |
| 金额更新 | 160 ms 局部淡入 | 直接显示最终金额，不做数字滚动 |
| 系统胶囊候选 | 网页约 320 ms 仅用于表达意图 | 实际形态、位置、展开和停留由荣耀系统控制 |

动画结束不能触发保存、累计金额或清空任务。减少动态开启时，关闭位移、缩放和 Dock 滑动，保留最终状态与文字反馈；取消动画不能卡住面板或业务。原生触感仅用于少量主动确认，后台每笔入账不默认震动。

## 荣耀适配安排

官方名称为“荣耀灵动胶囊”，第三方接入路径是 **YOYO 建议／全局触达 + Suggestions Kit**。公开场景以履约和出行为主，记账与 OCR 尚未确认准入。因此：

- 单笔成功、重复、待核对与权限问题：默认 App 内提示和清单反馈。
- 用户主动、确有持续时间的批量导入：准备系统胶囊候选稿与完整 App 内回退；申请通过后再接入。
- 胶囊候选文案只表达进度、数量和完成状态；锁屏默认不含商户与金额。
- 不以悬浮窗仿制系统胶囊，不为外观增加跨应用悬浮权限。
- 不按手机 1224px 物理宽度硬编码。以实际 dp、WindowInsets、开孔、安全区、字体和导航方式适配；目前预演不是 100 Pro 硬件精确复刻。

依据：[全局触达业务](https://developer.honor.com/cn/doc/guides/101452)、[接入与上线流程](https://developer.honor.com/cn/doc/guides/101455)、[设计规范](https://developer.honor.com/cn/doc/guides/101538)。完整能力和来源边界见 [HONOR-CAPSULE.md](HONOR-CAPSULE.md)。

## 交付与验收

### 0.3 使用指南扩展（2026-10-18）

沿用现有墨色清单、主题色和原生 BottomSheet，不新建另一套视觉系统。按 UI/UX Pro Max 的 Onboarding / User Freedom 建议，首次说明采用可跳过、可返回的四步图解：选应用授权、付款后自动检查、8 秒手动识别、核对结果。用章节进度、22sp 标题、16sp 正文和主题化矢量示意建立层级，不在一屏堆满权限说明。点按与最近任务手势由用户主动播放；减少动态时展示静态终态和完整文字。

首次关闭后不反复弹出；「自动」「设置」固定保留使用指南目录。阅读与授权分离，微信选择、页面读取、通知读取、截图同意各自有明确动作。手动识别面板保留目标选择，并随服务连接状态实时更新就绪按钮。所有正文可滚动，大字号时清单标题与状态上下排列，操作按钮保持至少 48dp 触区。

本轮按用户要求不运行模拟器；原生实际渲染、系统大字号、横屏和读屏效果留给真机验收，不能将源码检查写成视觉测试通过。

提示词按“总方向、页面、动效、验收”四层组织，见 [DESIGN-PROMPTS.md](DESIGN-PROMPTS.md)。它们固定产品任务、选定风格、状态、可复用组件和验收条件，比单写“高级、丝滑、像旗舰 App”更可执行。

### 0.4 支付宝真实页面图解（2026-10-18）

引导第二步用脱敏付款实图替代该步矢量示意，四步编号和手动识别入口保持不变。指南目录新增付款／转账／账单三类型图解，每次只显示一类，先展示金额与处理结论，再展示图片和易混淆字段。图片可点开全宽滚动大图，灰块的隐私含义在图例旁说明。保留首次跳过及自动／设置回看，不强制升级用户重看。

三张展示副本保留 8.60、298.00、-8.50 及广告／优惠数值，用于解释实付、转账跳过和历史账单核对；原始截图不进入 APK 或源码仓库。展示资源与遮盖清单见 [脱敏素材说明](../docs/GUIDE-ASSETS.md)，含原始信息的生成提示词仅本地保留。本轮实际查看了图片，未使用模拟器检查原生布局；原生显示与点按由用户真机测试。

核心验收包括：金额/列表/统计同步；待确认不计入统计；重复不累计；权限失效可恢复；隐藏金额覆盖所有显示位置；快速操作不出现旧状态覆盖；减少动态仍完成全部流程。进一步设计清单见 [INTERACTION-REVIEW.md](INTERACTION-REVIEW.md)。

当前只认定视觉方向已由用户选择。完整页面设计、原生帧率/耗电、大字体/横屏、真实权限、支付识别和胶囊准入不能仅凭网页预演标为通过。
